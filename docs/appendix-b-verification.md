# 怎样从文章结论核回锁定源码

[返回学习入口](00-start-here.md)

每条源码课程都使用提交级 GitHub 永久链接，因此不同读者能够看到同一版本的文件和行号。链接锁定的只是版本——机器只能检查「仓库、提交和路径存在」，无法判断文章的解释是否准确，所以复核时还要沿调用链亲自回答五个问题。

## 源码站点五问

1. 谁调用这段函数，它在真实产品路径上吗？
2. 输入来自模型、配置、用户还是已验证的内部对象？
3. 它修改了 Session、工具、文件还是仅修改局部投影？
4. 返回值代表调用完成、步骤完成还是任务完成？
5. 下一站在哪里，错误、取消和清理走哪条分支？

文章中的每个「第 N 站」都会给出这五项，以便你检查正文解释有没有越过源码真正能够支持的范围。

## 三类材料不要混用

| 材料 | 能支持 | 不能单独支持 |
| --- | --- | --- |
| Runtime 源码 | 该提交的实现和类型边界 | 运行时一定触发了这条路径 |
| 上游测试/Fixture | 构造场景下的可执行行为 | 未覆盖平台、真实 Provider 和长期负载 |
| 官方公开文档/协议 | 对外承诺与用法 | 闭源内部如何实现 |

边界不能混淆。在这里，公开 Agent SDK 源码只能用来核对 Transport、Messages、Permissions 和 Hooks 等公开契约，无法据此还原 Claude Code 内部的全部 Agent Loop。

## 从仓库根目录复核

```bash
npm run bootstrap
npm test
npm run check
```

- `bootstrap` 按 Source Lock 准备对应上游提交；
- `test` 运行本仓库脚本的单元测试；
- `check` 检查公共内容、链接、来源、图示和其他仓库规则。

这些命令只核对教材自身，不会调用六套 Harness 的付费模型，因此运行时不用准备相关模型账号。不过，它们无法代替目标项目自身的完整上游测试，因为本仓库并未覆盖上游项目的全部运行条件。如果要复核某条运行结论，还应进入对应的锁定 Checkout，按照官方要求运行最小相关测试，并记录 Node、Rust、Python 版本及跳过项。

## 判断一句话是否过度外推

尝试把一句结论改写成「在锁定提交的哪条路径、什么输入下，观察到了什么」，就能检查证据是否完整。如果其中任何一项填不出来，就应主动收窄这条结论能够覆盖的对象和条件。此时只能标为未核对、条件性支持、公开材料不可见，或仍需真实环境实验。
