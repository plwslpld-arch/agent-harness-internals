# 工程负责人：从任务契约到可恢复 Harness

## 适用角色

本路径面向负责 Agent 平台、开发者工具、模型接入、工具运行时或客户端协议的工程负责人。你需要把产品目标落实为可运行、可恢复、可观测的系统，同时解释模型、工具、权限、会话和外部副作用分别由谁负责。

它也适合正在选型的架构师。目标不是找一套功能最多的 Harness，而是把实际工作负载映射到共同抽象，再判断哪些能力使用上游默认实现，哪些必须由本地控制面补齐。

## 决策问题

先确定任务单位：一次请求、一个 Turn、一个可恢复 Session，还是拥有父子血缘的长期 Goal。随后确认模型输入怎样由系统提示、项目说明、历史、摘要、技能和运行态合成；只看最终 Prompt 会漏掉配置优先级与恢复边界。

工具链需要回答四个独立问题：Schema 是否进入模型表面，调用是否通过策略判断，真实执行发生在哪个操作系统边界，结果怎样回到下一轮。可从 [六类循环与工具比较](../comparisons/02-loop-tools-execution.md) 和 [权限、状态与恢复比较](../comparisons/03-permissions-state-recovery.md) 建立统一检查表。

最后决定服务化边界。若终端、网页、桌面和编辑器共同使用一个核心，服务端 Session、事件游标、初始快照、幂等和断线重连必须成为协议事实；窗口、草稿、格式和选中项仍属于客户端局部状态。参见 [编排、协议与表面比较](../comparisons/04-orchestration-protocol-surfaces.md)。

## 工作流

1. 写出一个最小任务契约，固定输入、期望产物、允许工具、权限规则、超时、取消语义和验收方式。用共同基础中的 [Agent 与 Turn](../foundations/02-agent-turn.md) 统一名称，避免团队把 Session、Turn 和 Trial 混用。
2. 画出端到端调用链，从入口和配置开始，经过模型流、工具决定、权限、执行、工具结果、持久化与恢复。每个跨进程或跨网络节点都记录标识、重试、去重、错误分类和外部副作用。
3. 为最危险的路径建立故障注入：模型流中断、工具超时、权限拒绝、进程崩溃、上下文溢出、事件乱序和断线重连。恢复后核对工作树、Session、外部系统与审计日志是否一致。
4. 把运行事件映射到统一 Artifact Schema，再由进程外 Scorer 验收最终产物。工程测试证明实现符合契约；它不能替代独立任务评测和发布门禁。

## 风险与边界

应用层批准规则不能冒充操作系统隔离。即使 Harness 会询问用户，执行进程仍可能继承文件系统、网络和凭据权限；高风险工具要放进容器、沙箱或专用远端执行器，并限制可写目录和出站网络。

压缩与恢复是两件事。摘要帮助控制模型上下文，却会有损丢失证据；持久 Session 保存消息，也未必恢复正在运行的子进程和外部事务。必须保存原始产物与摘要血缘，并对不可恢复副作用提供补偿或人工接管。

扩展代码拥有的权限通常高于说明型 Skill。Plugin、Hook、语言服务和远端工具都带来供应链与协议漂移风险，发现成功只表示链路起点。认证、能力枚举、模型可见、批准与执行结果要分别观测。

## 验收清单

- 任务、Turn、Session、Trial 和 Attempt 在接口与日志中含义稳定。
- 有效配置可解释，模型目录与真实请求分开验证，凭据不会进入产物。
- 每个工具调用都能关联 Schema、权限决定、执行边界、结果和副作用。
- 取消、超时、崩溃、压缩、恢复与重连都有自动化故障测试。
- 服务端事实与客户端局部状态分层，事件支持快照、游标、去重和作用域。
- 最终 Artifact 可由独立进程核验，不依赖模型最后一段自述。

## 自检

### 问题 1

工具返回成功是否说明任务完成？

**答案：** 不能。还要检查最终产物、外部副作用和任务验收条件，工具状态只覆盖调用局部。

### 问题 2

保存全部消息是否等于可以恢复？

**答案：** 不等于。进程、网络连接、锁、外部事务和工作树都可能拥有独立生命周期。

### 问题 3

多客户端为什么需要初始快照？

**答案：** 只订阅增量事件会漏掉连接前状态；快照与游标合并后才能安全重连和去重。

### 问题 4

何时应自建控制面？

**答案：** 当权限、恢复、审计、协议或部署责任超过上游公开契约时，应在外部建立可验证控制面，而不是依赖隐含默认值。
