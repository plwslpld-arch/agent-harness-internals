# 运维与安全负责人：建立可证明的运行边界

## 适用角色

本路径面向平台运维、安全工程、合规、站点可靠性和企业部署负责人。你需要控制 Agent 可读写的数据、可启动的进程、可访问的网络与凭据，并在模型、Harness、执行器、扩展服务和遥测后端之间划分信任边界。

它也适合评审自托管或混合部署方案的团队。源码存在某个策略接口，只证明可以配置；生产边界要由实际镜像、策略、身份、网络和审计证据确认。

## 学习目标

完成后，你应能为 Agent Harness 画出包含模型服务、核心控制器、执行器、扩展、遥测和 Artifact 存储的数据流与信任边界；能把工具可见、应用策略、用户批准、操作系统隔离和真实执行拆开验证；能设计短期身份、最小网络和文件权限，并在取消或崩溃后核对外部残留。

你还应能审查一份部署声明的证据强度。源码接口、单元测试、镜像配置、运行探针和生产审计分别支持不同结论；缺少实际部署记录时，结论保持未知。最终学习结果是可执行威胁模型、攻击演练与发布门禁，不是一个没有失败路径的安全功能清单。

## 前置知识

需要理解进程权限、容器或沙箱、文件挂载、网络出口、身份与密钥管理、日志留存和基本事件响应。建议先读共同基础中的工具权限与 Sandbox、Session 与恢复，以及横向比较中的权限状态恢复；不要求掌握某个云平台的专用产品。

实验环境必须与日常工作目录和生产账号隔离。准备临时文件树、本地回环服务、一次性测试凭据和可销毁容器；路径逃逸、网络外带和命令注入只针对这些夹具。凭据本身不得写入 Prompt、日志、截图或版本库，审计记录只保存不可逆摘要和作用域。

## 决策问题

先制作数据流与威胁模型：用户输入、仓库、系统提示、模型请求、工具参数、外部服务、日志和分享副本分别经过哪里？每个边界记录数据分类、身份、加密、保留、地域和删除责任。

然后区分应用批准与执行隔离。批准策略决定 Harness 是否允许调用，操作系统边界决定进程实际上能访问什么。两层都要有，但它们不能互相替代；可从 [权限、状态与恢复比较](../comparisons/03-permissions-state-recovery.md) 核对六条主线的公开边界。

最后确定扩展供应链和维护模型。Skill、Plugin、Hook、MCP、语言服务与子任务具有不同权限和升级路径。要知道谁安装、谁审核、如何锁版本、怎样撤销信任，以及连接失败或协议漂移时如何降级。

## 工作流

1. 建立资产与身份清单：模型提供方、Harness 服务、执行器、插件、远端工具、遥测后端和产物存储。为人、服务、任务和子任务分配最小身份与作用域，不共享长期高权限令牌。
2. 按任务风险设计执行配置。只读任务限制写入；代码任务使用临时工作树和受限网络；高风险外部操作采用专用执行器、短期凭据、双重确认与幂等键。
3. 运行故障与攻击演练：提示注入诱导读取秘密、路径逃逸、命令注入、扩展篡改、远端工具伪造、事件丢失、凭据过期和取消后进程残留。用系统事实验证防线，不接受模型自述。
4. 建立发布与回滚门禁。镜像、配置、来源锁、策略和迁移脚本都要可追溯；先在隔离环境运行固定 Trial，再分批发布并监控错误、权限拒绝、成本和副作用。
5. 定义留存与事故响应。消息、工具参数、文件、Trace、Feedback 和分享副本分别设置脱敏、访问、保留与删除，演练密钥撤销、会话隔离和证据保全。

## 实践任务

为一个本地代码修改 Harness 建立威胁模型。列出资产、主体、入口、信任边界和至少八个滥用案例，其中必须包含提示注入读取秘密、符号链接逃逸、批准后参数替换、插件供应链篡改、MCP 伪造结果、遥测泄漏、取消后残留进程和已提交副作用重复执行。

随后实现三层测试控制：应用策略给出 allow、ask、deny；fixture Sandbox 限制目录与网络；执行器记录真实副作用。为项目内写入、项目外写入和本地请求运行组合矩阵，证明策略拒绝路径零执行、策略允许但 Sandbox 可阻断、Sandbox 允许不代表任务获批。再让 Hook、审批通道和隔离准备分别故障，检查是否失败关闭。

最后制作一份部署与事故演练包。锁定镜像、策略、扩展和来源，运行固定 Trial；模拟凭据泄漏后撤销令牌、隔离 Session、停止子进程、保存证据并生成影响范围。报告中区分教学夹具、预生产探针和真实生产证据，不能用其中一类替代另一类。

再增加一次策略漂移演练：保留相同镜像，只修改一条允许规则或网络出口，运行前后生成规范化配置差异，并确认高风险扩大需要独立批准。若客户端缓存旧策略，服务端必须拒绝过期决定；若远端执行器版本不匹配，任务进入阻断状态，不能静默退回宿主机。

遥测验证采用端到端对账。对同一 Trial 比较本地生成事件、导出队列接受数、后端确认数和删除后剩余数，分别制造采样、断网和后端拒绝。缺失事件必须标成未采集、未导出或未确认，不能解释为零风险；脱敏测试则用合成 Secret 检查 Prompt、错误、路径和分享副本都没有泄漏原值。

事故复盘不仅写「已修复」。要列出最早可检测信号、受影响主体、可能副作用、证据缺口、临时遏制、永久控制和验证命令。若某项外部状态无法核验，就把范围标为未知并给出持续观察或人工处置，不得因没有日志就判定没有影响。

## 风险与边界

允许工具列表不是可用性或隔离证明。工具可能未安装、版本不符或连接失败；即使成功执行，子进程仍可能继承宿主环境和网络。部署证据必须覆盖真实用户、目录、容器、挂载和出站规则。

提示注入无法只靠系统提示解决。外部内容可诱导模型调用已授权工具，因此敏感数据访问、外发和破坏性操作要由策略、最小权限、数据标记和人工控制共同限制。

遥测能帮助调查，也会扩大敏感数据面。关闭消息正文仍可能从路径、命令和错误中泄露信息；采集最小化、字段级脱敏和访问审计要在导出前执行，并验证后端删除流程。

多客户端和远端子任务增加身份混淆风险。每个事件、Artifact 和副作用必须关联项目、Session、Task、用户与服务身份；重连不能让旧客户端获得新作用域，取消确认也不能替代进程与外部事务核对。

## 验收清单

- 数据流、身份、信任边界和责任主体有版本化图与清单。
- 应用批准和操作系统隔离分别配置、测试和审计。
- 凭据短期化、最小化，不进入 Prompt、日志、Artifact 或公开分享。
- 扩展来源、完整性、版本、权限和撤销流程可核对。
- 取消、超时、崩溃与重连后检查进程、文件、网络和外部事务。
- 遥测采集、脱敏、留存、地域、访问和删除均有实际部署证据。
- 发布支持分批、监控、停止与回滚，严重副作用拥有独立门禁。

## 作品证据

作品集应包含版本化数据流图与威胁模型、权限和隔离组合矩阵、攻击脚本的无害夹具、事件 JSONL、镜像与策略摘要、遥测字段清单、留存删除测试和事故复盘。每项控制都要引用对应威胁与验证结果，避免只列最佳实践。

验收者应能看到至少一个防线被绕过后由下一层阻断的案例，也要看到一个无法自动判定而进入人工处置的案例。作品必须明确不证明真实托管服务内部实现、生产合规认证或绝对安全；它证明的是锁定测试环境中的边界、失败关闭和证据保全流程可以复现。

再附一份残余风险登记表，为每项风险写主体、影响、现有控制、检测、处置人和复核日期。未知项不能填成低风险；需要外部供应商或生产配置才能验证的项目，明确依赖和截止条件，使安全结论能随证据更新，而不是一次评审后永久有效。

每次依赖、镜像、策略或扩展升级后，重新运行受影响探针并更新登记表；未复测期间相应能力标记为过期，不沿用旧版本的通过结论。

## 自检

### 问题 1

工具调用需要用户批准，是否已经形成沙箱？

**答案：** 没有。批准是应用决策，沙箱需要操作系统或远端执行边界限制真实能力。

### 问题 2

取消任务后最先核对什么？

**答案：** 核对进程、文件、网络请求、锁和外部事务是否仍在运行，再处理 Session 状态。

### 问题 3

扩展成功加载说明什么？

**答案：** 只说明发现或初始化阶段成功，还要验证来源、权限、协议、模型可见、调用与副作用。

### 问题 4

为什么遥测后端也属于高风险边界？

**答案：** 它可能集中保存 Prompt、代码、路径、命令和身份信息，需要独立访问、保留与删除治理。
