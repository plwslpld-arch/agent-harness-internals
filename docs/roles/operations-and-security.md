# 运维与安全负责人：建立可证明的运行边界

## 适用角色

本路径面向平台运维、安全工程、合规、站点可靠性和企业部署负责人。你需要控制 Agent 可读写的数据、可启动的进程、可访问的网络与凭据，并在模型、Harness、执行器、扩展服务和遥测后端之间划分信任边界。

它也适合评审自托管或混合部署方案的团队。源码存在某个策略接口，只证明可以配置；生产边界要由实际镜像、策略、身份、网络和审计证据确认。

## 决策问题

先制作数据流与威胁模型：用户输入、仓库、系统提示、模型请求、工具参数、外部服务、日志和分享副本分别经过哪里？每个边界记录数据分类、身份、加密、保留、地域和删除责任。

然后区分应用批准与执行隔离。批准策略决定 Harness 是否允许调用，操作系统边界决定进程实际上能访问什么。两层都要有，但它们不能互相替代；可从 [权限、状态与恢复比较](../comparisons/03-permissions-state-recovery.md) 核对六条主线的公开边界。

最后确定扩展供应链和维护模型。Skill、Plugin、Hook、MCP、语言服务与子任务具有不同权限和升级路径。要知道谁安装、谁审核、如何锁版本、怎样撤销信任，以及连接失败或协议漂移时如何降级。

## 工作流

1. 建立资产与身份清单：模型提供方、Harness 服务、执行器、插件、远端工具、遥测后端和产物存储。为人、服务、任务和子任务分配最小身份与作用域，不共享长期高权限令牌。
2. 按任务风险设计执行配置。只读任务限制写入；代码任务使用临时工作树和受限网络；高风险外部操作采用专用执行器、短期凭据、双重确认与幂等键。
3. 运行故障与攻击演练：提示注入诱导读取秘密、路径逃逸、命令注入、扩展篡改、远端工具伪造、事件丢失、凭据过期和取消后进程残留。用系统事实验证防线，不接受模型自述。
4. 建立发布与回滚门禁。镜像、配置、来源锁、策略和迁移脚本都要可追溯；先在隔离环境运行固定 Trial，再分批发布并监控错误、权限拒绝、成本和副作用。
5. 定义留存与事故响应。消息、工具参数、文件、Trace、Feedback 和分享副本分别设置脱敏、访问、保留与删除，演练密钥撤销、会话隔离和证据保全。

## 风险与边界

允许工具列表不是可用性或隔离证明。工具可能未安装、版本不符或连接失败；即使成功执行，子进程仍可能继承宿主环境和网络。部署证据必须覆盖真实用户、目录、容器、挂载和出站规则。

提示注入无法只靠系统提示解决。外部内容可诱导模型调用已授权工具，因此敏感数据访问、外发和破坏性操作要由策略、最小权限、数据标记和人工控制共同限制。

遥测能帮助调查，也会扩大敏感数据面。关闭消息正文仍可能从路径、命令和错误中泄露信息；采集最小化、字段级脱敏和访问审计要在导出前执行，并验证后端删除流程。

多客户端和远端子任务增加身份混淆风险。每个事件、Artifact 和副作用必须关联项目、Session、Task、用户与服务身份；重连不能让旧客户端获得新作用域，取消确认也不能替代进程与外部事务核对。

## 验收清单

- 数据流、身份、信任边界和责任主体有版本化图与清单。
- 应用批准和操作系统隔离分别配置、测试和审计。
- 凭据短期化、最小化，不进入 Prompt、日志、Artifact 或公开分享。
- 扩展来源、完整性、版本、权限和撤销流程可核对。
- 取消、超时、崩溃与重连后检查进程、文件、网络和外部事务。
- 遥测采集、脱敏、留存、地域、访问和删除均有实际部署证据。
- 发布支持分批、监控、停止与回滚，严重副作用拥有独立门禁。

## 自检

### 问题 1

工具调用需要用户批准，是否已经形成沙箱？

**答案：** 没有。批准是应用决策，沙箱需要操作系统或远端执行边界限制真实能力。

### 问题 2

取消任务后最先核对什么？

**答案：** 核对进程、文件、网络请求、锁和外部事务是否仍在运行，再处理 Session 状态。

### 问题 3

扩展成功加载说明什么？

**答案：** 只说明发现或初始化阶段成功，还要验证来源、权限、协议、模型可见、调用与副作用。

### 问题 4

为什么遥测后端也属于高风险边界？

**答案：** 它可能集中保存 Prompt、代码、路径、命令和身份信息，需要独立访问、保留与删除治理。
