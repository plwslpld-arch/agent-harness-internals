# 质量与评测负责人：建立独立证据链

## 适用角色

本路径面向 AI Quality、评测平台、测试、数据和发布治理负责人。你的任务是把 Harness 运行证据变成可重复的 Trial、可解释的 Score 和独立发布判断，同时阻止日志、用户反馈或上游测试被误写成质量结论。

它也适合准备把评测结果接入 DPO、GRPO 或 RFT 的团队。训练奖励、Checkpoint 选择与独立 Release Eval 应共享血缘，却保持数据、评分器和责任隔离；完整责任链见 [可观测性、独立评测与部署维护](../comparisons/05-observability-eval-deployment.md)。

## 决策问题

第一项决策是统计单位。Dataset 条目与 Target 版本共同形成 Trial，Trial 的分母在运行前冻结；Attempt 只记录恢复。基础设施故障可以重试，产品失败必须保留，不能用成功的后续尝试覆盖。

第二项决策是评分语义。规则 Scorer、模型裁判和人工复核分别适合哪些维度？每个 Score 需要方向、范围、缺失值、聚合、置信度和版本。若无法解释 0.8 的业务含义，就不能拿它跨场景排名。

第三项决策是独立性。训练集、开发集、候选选择集和发布 Holdout 如何隔离，谁能看到答案，谁能修改阈值，谁签署发布？使用同一数据和评分器反复优化后，原结果不再是独立证据。

## 工作流

1. 写 Dataset Contract：任务 ID、输入快照、环境、允许工具、期望 Artifact、污染规则、风险标签和验收维度。把每项任务映射到至少一个真实用户场景，不用随机题目数量冒充覆盖率。
2. 写 Run Contract：Target、Harness、模型、配置、种子策略、资源上限、超时、重试分类和环境指纹。规范 Attempt 的选择规则必须在看到结果前确定。
3. 写 Scorer Contract：输入 Artifact、输出 Schema、分数语义、失败原因、版本、测试夹具与人工校准。对模型评分器固定提示和模型，并保存原始判断与分歧。
4. 建立 RewardAdapter 能力声明。只有 Score 的方向、范围、缺失值、聚合与裁剪全部明确时才输出可训练 Reward；否则标记 partial 或 unavailable。
5. 在候选冻结后运行独立 Holdout，报告样本量、区间、失败簇、回归、成本和豁免。发布结论引用 Trial 与 Artifact，不引用单张汇总截图。

## 风险与边界

上游单元测试证明代码路径符合项目预期，不能证明你的任务分布、部署配置或模型行为达标。Telemetry 提供可追溯输入，也不会自动形成 Dataset、Scorer 或发布阈值。

模型评分器可能偏爱措辞、长度或自己的答案风格。要用对抗样本、规则核验、双盲人工集和跨版本复测寻找投机；高风险维度不能只依赖单一模型裁判。

平均分会掩盖严重失败。发布报告至少按场景、风险、工具类型和失败原因分层，预先定义不可接受事件。低频破坏性副作用不能被大量简单通过样本稀释。

评测 Artifact 可能包含客户代码、提示、工具参数和个人信息。采集、脱敏、访问、保留、地域与删除必须和生产策略一致；公开仓库中的合成样本不证明生产合规。

## 验收清单

- Dataset、Target、Harness、Scorer 和环境均有不可变版本标识。
- Trial 分母固定，Attempt 恢复规则不会覆盖产品失败。
- Score 输出包含语义、失败原因、证据引用和评分器版本。
- RewardAdapter 对完整、部分和不可用语义有明确能力契约。
- 训练、候选选择与发布 Holdout 分区并保留访问审计。
- 报告展示区间和失败簇，不用单一平均分或排行榜替代判断。

## 自检

### 问题 1

网络错误重试成功后，Trial 应怎样记？

**答案：** 保留两个 Attempt，按预先规则选择规范 Attempt；重试不能改变 Trial 身份和分母。

### 问题 2

什么时候 Score 可以转成 Reward？

**答案：** 当方向、范围、缺失值、聚合、裁剪和版本语义完整，并通过训练适配测试时。

### 问题 3

为什么还要独立发布集？

**答案：** 训练和选择会适应已见数据与评分器，独立集用于检测过拟合、投机和场景退化。

### 问题 4

平均分上涨是否足够发布？

**答案：** 不足。还要检查不确定性、关键场景、严重失败、副作用、成本和预设门槛。
