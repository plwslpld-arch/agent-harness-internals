# 不写代码也要懂的：agent harness 到底是什么

*这一篇讲给产品、运营、以及任何不打算读源码的人。全篇零代码。读完你能回答：AI 编程工具里「模型」和「工具本身」各负责什么、为什么长对话越用越贵、为什么它会突然「忘事」、以及各家产品的差别到底差在哪。*

用 AI 编程工具的人大多有过这三种体验：聊到后面越来越慢、账单比预想的高；某个说过的细节它突然就不记得了；同事说「它会先问你一声再改文件」，你这儿却从来不问。

这三件事看着不相干，其实是同一层东西决定的，而且那一层不是模型。

---

## 一、先把一件事分清楚：模型 ≠ 产品

你用 Cursor、Claude Code、通义灵码这类 AI 编程工具时，感觉是在「跟一个会写代码的 AI 对话」。

实际上你在跟**两层东西**打交道：

- **模型**（DeepSeek-V4、Claude、GPT 这些）：它只会做一件事：你给它一段文字，它续写一段文字。仅此而已。它没有记忆，不会读文件，不会执行命令，甚至不知道现在几点。
- **harness**（中文常译「外壳」或「支架」）：包在模型外面的那层程序。**你感受到的几乎所有「智能」，一半来自它。**

harness 干四件事：

| 它做什么 | 没有它会怎样 |
|---|---|
| **拼上下文** | 模型不知道你在哪个项目、上一句说了什么、这个仓库有什么规矩 |
| **调工具** | 模型说「我要读 a.txt」，得有人真的去读，再把内容喂回去 |
| **管权限** | 模型说「删掉这个目录」，得有人决定这事能不能干 |
| **记轨迹** | 崩溃了、断网了、你关掉窗口了，得能接着跑 |

DeepSeek Harness（简称 dsh）就是 DeepSeek 在 2026 年 8 月开源的这么一层。这个仓库是它的源码分析。

**一句话记住**：模型决定「聪不聪明」，harness 决定「好不好用、贵不贵、会不会出事」。

---

## 二、模型其实没有记忆

这是最反直觉的一点，但它解释了后面所有事。

模型**每一次**回答，都是从零开始读一遍全部内容。你跟它聊到第 50 轮，它并不是「记得」前面 49 轮。是这一次请求里，把前面 49 轮**原样重新发了一遍**给它。

所以：

- 对话越长，每次发的东西越多；
- 每次发的东西越多，**每次都要重新收费**；
- 到某个长度，模型一次能读的量就到顶了（这个上限叫**上下文窗口**）。

这三条推论直接对应了后面三节：为什么贵、为什么会忘事、为什么各家都在拼命优化同一件事。

---

## 三、为什么长对话会越用越贵，以及怎么变便宜

### 问题

第 1 轮发 1,000 字，第 50 轮可能要发 50,000 字。而计费是按「这次发了多少」算的。所以长对话的成本不是线性增长，是**平方级**增长。

### 解法：缓存

模型服务商都提供一种叫**前缀缓存**的机制：

> 如果这次发的内容，**开头一大段**和上次一模一样，那开头这段就不用重新算了，直接用上次的结果，收费便宜很多（DeepSeek 的公开定价是一折左右）。

关键词是**开头**。缓存是从第一个字开始逐字比对的，**只要开头改了一个字，后面全部作废**，哪怕后面几万字一模一样。

各家的接法不太一样：DeepSeek 和 OpenAI 是服务端自动认前缀，客户端管住自己别乱动就行；Anthropic 要客户端自己在请求里打标记（最多打四处），说清楚「缓存到这儿」。下面讲的都是自动认前缀这一类。

我们用真实 API 实测过这件事（数据在仓库的 `research/runtime-evidence/`）：

| 情况 | 缓存命中率 |
|---|---|
| 开头不动，只在末尾追加新内容 | **81%–96%** |
| 只把开头第一句话改了几个字 | **0%** |

从 85.7% 掉到 0，就因为改了开头一句话。

### 所以 harness 的核心功力在这里

一个设计得好的 harness，会把**永远不变的东西放最前面，把会变的东西全部赶到最后面**。

举个真实例子：你在工具里把权限从「可以改文件」切成「只读」。这条状态要告诉模型。放哪？

- 放开头（跟身份说明写在一起）：每切一次权限，整个对话的缓存全废；
- 放末尾（作为一条新消息追加）：前面全部照常命中。

dsh 选了后者。上游为此留了实测记录，我们也独立复测了：

| 做法 | 切换后的命中率 |
|---|---|
| 权限状态写在开头 | 33%（只剩开头 256 个 token 还有效） |
| 权限状态追加在末尾 | 81% |

**产品含义**：同样的功能、同样的模型，两种实现方式的账单可以差好几倍。用户感觉不到区别，财务能感觉到。

## 四、为什么它会突然「忘事」

上下文窗口是有上限的。到了上限怎么办？两种办法：

1. **直接报错**（有些极简工具就这么做，比如 mini-swe-agent，任务直接失败）；
2. **压缩**：把前面一大段对话交给模型自己总结成一段摘要，用摘要替换掉原文。

绝大多数产品选第二种，这个动作一般叫 compact（压缩）或 summarize（摘要）。

**代价是真实的**：摘要必然丢信息。你会发现「刚才明明说过的细节，它现在不记得了」。不是模型变笨了，是那段原文已经被换成摘要了。

各家的差别在于**怎么压**：

| 产品 | 做法 |
|---|---|
| **Claude Code** | 先清掉旧的工具输出，还不够再摘要；压完把项目说明文件从磁盘重新读一遍塞回去 |
| **Codex** | 保留最近 2 万 token 以内的用户消息 + 摘要；有三套实现互相兜底 |
| **dsh** | 从最早的消息开始压，保留末尾一段，绝不把「工具调用」和「它的结果」拆开 |
| **pi** | 保留最近 2 万 token，**绝不在工具结果处切断** |
| **mini-swe-agent** | 不压缩，撞上限直接结束任务 |

有个共同的坑：**压缩本身也要花钱**。因为要把前面那一大段发给模型让它总结，这又是一次大请求。dsh 在这里做了个巧活，让这次「总结请求」跟主对话的开头**逐字节相同**，于是这部分也能命中缓存。我们实测：这么做能拿到 93.4% 的命中率，而换一种写法（给总结任务另写一段开头）是 **0%**。

**产品含义**：「压缩」这个功能的体验好坏，取决于三件事：什么时候触发、砍掉哪一段、压完还记得什么。这三件事各家都不一样，值得在选型时问清楚。

## 五、为什么有时候弹窗问你，有时候不问

AI 要执行 `rm -rf` 这种命令，该不该问你一声？

这里有**两套独立的机制**，很多人会混为一谈：

- **审批（approval）**：弹窗问人。决定「这件事要不要做」。
- **沙箱（sandbox）**：操作系统级的隔离。决定「就算它做了，能碰到什么」。

用一句话区分：**审批决定要不要跑，沙箱决定跑起来能碰到什么。**

只有审批没有沙箱，等于把安全责任推给用户：用户点「同意」点到麻木，就没有防护了。只有沙箱没有审批，则要求沙箱把「这是策略拒绝」明明白白告诉模型，否则模型只会换个写法一遍遍重试。dsh 走的就是后一条路，所以它在拒绝信息上花了功夫。

各家的选择差别很大：

| 产品 | 审批 | 系统级沙箱 |
|---|---|---|
| **Claude Code** | 6 种权限模式，其中一种用**第二个模型**当自动审核员 | 有（macOS/Linux；原生 Windows 没有） |
| **Codex** | 四档策略 + 一套「被拒后申请升级」的流程 | 有（三平台都有） |
| **dsh** | 默认**不弹窗**，只在沙箱拒绝后模型主动请求升级时才弹（挂了 hook 桥可以再多一条路，默认组合没挂） | 有（Windows 上只兑现一部分） |
| **OpenCode** | 完整的规则引擎，能识别 bash 命令结构 | **没有** |
| **pi** | **刻意不做**，官方建议直接跑在容器里 | 没有 |

注意 dsh 那行：很多人以为「AI 要改文件会先问我」，**默认组合下并不会**。它靠沙箱兜底，被沙箱拦住之后模型才会来申请权限。

**产品含义**：选型时问「有没有权限管理」是问不到点子上的，要问「是审批还是沙箱、原生 Windows 上有没有」。

## 六、这五家产品的定位差别

我们对六个 harness（含闭源的 Claude Code）做了七个维度的机制对照，完整版在 [横向对照](14-comparison.md)。这里只给结论：

| 产品 | 一句话定位 | 适合谁 |
|---|---|---|
| **mini-swe-agent** | 190 行跑通一个编程 agent，主张「外壳越薄越好，复杂度该在模型里」 | 研究、做评测、想搞明白最小可行结构 |
| **pi** | 不做权限、不做子代理、不接 MCP，但把循环、缓存、压缩三件核心事做扎实 | 喜欢极简、自己有容器隔离能力的人 |
| **OpenCode** | 功能完整、工程成熟，按模型家族分别调提示词 | 想要开箱即用的团队 |
| **Codex** | Rust 核心，提示词由服务端下发（升级不用发新版客户端），沙箱三平台齐全 | 企业环境、看重安全边界 |
| **Claude Code** | 功能面最广，权限和上下文管理做得最细；**闭源** | 大多数个人和团队用户 |
| **dsh** | 一切皆插件，连主循环本身都能替换 | 想在上面长出自己产品的团队 |

**没有哪个是对的。** 差别在于你要的是「一个能用的编程 agent」，还是「一个能长出很多种 agent 的底座」。

## 七、几个会在文档里反复出现的词

| 词 | 一句话解释 |
|---|---|
| **harness** | 包在模型外面的那层程序。本仓库研究的对象。 |
| **system prompt** | 每次请求发给模型的开场白，交代身份、能力、规矩。用户看不见。 |
| **上下文窗口** | 模型一次能读的最大量。超了就得压缩或报错。 |
| **token** | 模型计量文字的单位。中文大致 1 个字 ≈ 1–2 个 token。 |
| **前缀缓存** | 开头内容和上次相同就不重算，按一折左右收费。 |
| **压缩 / compact** | 上下文快满时把旧对话总结成摘要，腾出空间。 |
| **工具（tool）** | 模型能调用的动作，比如读文件、跑命令、搜网页。 |
| **子代理（subagent）** | 主 agent 派出去干一件独立事情的另一个 agent，有自己的上下文。 |
| **MCP** | 一个开放协议，让外部程序把自己的工具接给 AI 用。现在是事实标准。 |

更完整的（60 条，每条带源码出处）见 [附录 A 术语表](appendix-a-glossary.md)。

## 自检

**Q1：为什么说「模型没有记忆」，但你用起来它明明记得上文？**

因为每次请求都把前面的对话**原样重发**了一遍。「记得」是 harness 重发出来的效果，不是模型自己存住了。这也解释了为什么长对话贵、为什么会有上下文窗口上限。

**Q2：同样接 DeepSeek 的两个产品，一个月账单可能差好几倍，最可能差在哪？**

差在缓存命中率。核心是「会变的信息放在请求的开头还是末尾」。放开头，每变一次整段缓存作废；放末尾，前面照常命中。实测差距是 33% 对 81%，而用户完全感觉不到两者的区别。

**Q3：「这个工具有权限管理」这句话为什么信息量不够？**

因为审批和沙箱是两回事。审批是弹窗问人，沙箱是操作系统级隔离。只有审批的产品（比如 OpenCode）在用户点习惯「同意」之后就没有防线了；而 dsh 默认根本不弹窗，靠沙箱兜底。要问的是「是哪一种、原生 Windows 上有没有」。
