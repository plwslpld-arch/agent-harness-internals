# 按经验选择阅读路线

同一篇源码导读会给不同读者带来不同收获，因此不必把「从头到尾读完所有文件」设成学习目标。更有效的读法是先回答当前层级的问题，等主线清楚以后再进入更深的实现。

## Starter：先建立一条完整任务链

这一层适合刚接触编程智能体，并且只熟悉一种编程语言的读者。

第一遍阅读时，只关注这五个直接决定任务主线的问题：

- 项目从哪里接收用户任务；
- 模型请求工具时产生什么数据；
- 工具结果怎样回到下一轮；
- 哪个条件让循环结束；
- 一次失败会在哪里被看到。

Provider 兼容层、终端渲染、遥测导出、发布脚本和大量边界类型都可以暂时跳过。学完这一层以后，你不必背出文件名，只要能合上文档画出一次任务的主链，就算达到了目标。

可以先读五篇基础导读，再看 pi 或 DeepSeek Harness 的系统地图，随后进入对应课程中的 Agent Loop、工具和 Session 章节。

## Builder：解释一个变量怎样改变行为

这一层适合正在搭建智能体、工具系统或编程智能体的工程师。

看清完整任务链以后，再继续追踪这些会改变系统行为的变量：

- 配置怎样进入模型请求；
- Tool Schema、调用参数和结果消息怎样转换；
- 可见、允许、批准和可执行为何是四层不同判断；
- Steering、Follow-up、Hook、Extension 或子 Agent 在循环哪个位置介入；
- Session 恢复和压缩怎样改变下一轮输入。

到了这一层，实现和测试需要对照着读，因为只看其中一边很难确认行为是怎样发生的。每完成一章，可以选择一个配置或状态字段，再沿调用链说明它如何改变最终行为。

可以先完整读完任意一条课程，再选择架构不同的第二条课程，最后阅读对应的横向比较。

## Maintainer：判断结论能否持续被核对

这一层适合负责 Harness 维护、安全治理、可观测性或评测系统的读者。

到了维护阶段，阅读重点要转向这些长期运行和核对问题：

- 错误是否被正确分类，而不是统一重试；
- 并发执行是否保留确定性的历史顺序；
- 权限拒绝、系统能力不足和工具失败能否区分；
- Session、Trace 和结果产物能否建立稳定关联；
- 上游升级后，哪些源码锚点和解释会失效；
- Eval 是否独立判定任务结果，而不是相信模型自述。

到了这一层，你需要完成确定性实践、检查上游测试，还要为自己关心的机制写出最小复现。由于一次演示成功无法证明系统在其他任务、平台或部署条件下同样可靠，验证范围也必须随结论一起说明。

## 怎样在一篇文章中切换层级

每篇源码课的主体都面向 Builder，不过也会保留三类入口，方便不同阶段的读者找到合适的切入点：

- 开头的「先看问题」和流程图供 Starter 建立直觉；
- 中间的源码站点、状态变化与设计解释供 Builder 深读；
- 末尾的核对方法、失败路径和开放问题供 Maintainer 验证。

如果某篇第一遍读不懂，可以先回到课程 README 的系统地图，确认当前模块位于模型之前、工具执行之间还是结果之后。位置一旦确定下来——代码里的调用关系通常就容易理解了。
