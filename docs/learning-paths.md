# 按经验选择阅读路线

同一篇源码对不同读者的价值不同。不要把「从头到尾读完所有文件」当成学习目标；更有效的方法是先回答当前层级的问题，再进入更深的实现。

## Starter：先建立一条完整任务链

适合刚接触编程智能体、只熟悉一种编程语言的读者。

第一遍只关注：

- 项目从哪里接收用户任务；
- 模型请求工具时产生什么数据；
- 工具结果怎样回到下一轮；
- 哪个条件让循环结束；
- 一次失败会在哪里被看到。

暂时跳过 Provider 兼容层、终端渲染、遥测导出、发布脚本和大量边界类型。完成标志不是记住文件名，而是能不看文档画出一次任务的主链。

推荐路线：五篇基础导读 → pi 或 DeepSeek Harness 的系统地图 → 对应课程中的 Agent Loop、工具和 Session 章节。

## Builder：解释一个变量怎样改变行为

适合正在搭建智能体、工具系统或编程智能体的工程师。

在完整任务链上继续追踪：

- 配置怎样进入模型请求；
- Tool Schema、调用参数和结果消息怎样转换；
- 可见、允许、批准和可执行为何是四层不同判断；
- Steering、Follow-up、Hook、Extension 或子 Agent 在循环哪个位置介入；
- Session 恢复和压缩怎样改变下一轮输入。

这一层应当同时阅读实现和测试。每完成一章，选择一个配置或状态字段，沿调用链说明它如何改变最终行为。

推荐路线：完整读完任意一条课程 → 选择第二条不同架构的课程 → 阅读对应横向比较。

## Maintainer：判断结论能否持续被核对

适合维护 Harness、做安全治理、可观测性或评测系统的读者。

重点转向：

- 错误是否被正确分类，而不是统一重试；
- 并发执行是否保留确定性的历史顺序；
- 权限拒绝、系统能力不足和工具失败能否区分；
- Session、Trace 和结果产物能否建立稳定关联；
- 上游升级后，哪些源码锚点和解释会失效；
- Eval 是否独立判定任务结果，而不是相信模型自述。

这一层应完成确定性实践，检查上游测试，并为自己关心的机制写出最小复现。一次演示成功不能证明系统在其他任务、平台或部署条件下同样可靠。

## 怎样在一篇文章中切换层级

每篇源码课的主体都面向 Builder，但会提供三类入口：

- 开头的「先看问题」和流程图供 Starter 建立直觉；
- 中间的源码站点、状态变化与设计解释供 Builder 深读；
- 末尾的核对方法、失败路径和开放问题供 Maintainer 验证。

如果某篇第一遍读不懂，先回到课程 README 的系统地图，确认当前模块位于模型之前、工具执行之间还是结果之后。定位清楚以后，再读代码通常会容易很多。
